# 开发日志 · 飞牛歌词同步（musicTB）

> 记录决策、踩坑与修复。时间均为北京时间。

## 2026-11-18 · 立项

- 需求：飞牛 NAS 的音乐库下载后没有歌词，需要批量补全。
- 关键约束：运行在 fnOS 上；用户从应用商店安装；不依赖用户 NAS 的特定端口。
- 命名：技术标识 `musictb`，显示名「飞牛歌词同步」。

### 调研结论（fnOS 应用机制）

- 应用包 = `.fpk`（gzip 压缩的 tar），内含 `manifest`、`config/{privilege,resource}`、`cmd/` 生命周期脚本、`app/`、`wizard/`、图标。
- 安装后：`/var/apps/{app}`，`target` → `/vol{n}/@appcenter`，`var` → `@appdata`。
- 应用以独立包用户运行，**默认无权访问用户文件**，需用户/管理员授权目录。
- 两套入口方案：端口服务（iframe 直连端口）或**统一网关**（`/app/{appname}`，经系统转发）。
- 运行时可用系统依赖应用：`install_dep_apps=nodejs_v22`。

### 歌词源实测（本机直连）

| 源 | 结论 |
|---|---|
| LRCLIB | 可用，但响应 10~20s，不适合做主力 |

## 2026-11-18 · 第一版（0.1.0）

- 结构：Node 后端 + 原生 JS 单页，扫描 → 匹配 → 取词 → 写 `.lrc`。
- 内嵌歌词写入用 `node-taglib-sharp`（实测写入后可读回）。
- 打包：Windows 版 fnpack。

## 2026-11-18 · 性能与匹配（0.2.x）

- **两阶段匹配**：先按元数据排序，只给前 N 个候选取歌词 → 请求量降到约 1/4，单曲搜索 21s → 5.6s。
- **快源优先 + 慢源兜底**：LRCLIB 慢，只在快源结果不佳时调用 → 搜索 0.3~0.9s。
- **源熔断**：某源连续失败 2 次冷却 5 分钟。
- **曲库写入节流**：不再每处理一首就重写整个 `library.json`。

## 2026-11-18 · 真机部署踩坑（重要）

1. **`.fpk` 权限**：Windows 版 fnpack 打出的包内 `cmd/*` 是 `0666`，**无执行位** → fnOS 调不起 `cmd/main` → 服务不启动 → 应用窗口白屏/云朵错误页。
   - 修复：自写 tar 打包器，强制 `cmd/*` 0755、目录 0755、普通文件 0644。
2. **`.fpk` 必须 gzip**：裸 tar 会被判「不是有效的 fpk 文件」。
   - 校验：文件头必须是 `1f 8b`。
3. **端口依赖**：最初用固定 8791，用户公网只转发 5000 → iframe 连不上。
   - 修复：改用**统一网关** `/app/musictb`，服务监听 `target/app.sock`；TCP 端口交给系统分配（写 `var/port.txt`），不再占固定端口。
   - 网关会把前缀原样带过来，后端需剥离 `/app/musictb`，前端资源改用相对路径。
4. **文件访问权限**：包用户对 `/vol1/1000/Music` 可直接读，但写入需系统 ACL。
   - 修复：扫描时做写探测，无权限在界面黄条提示，并要求在应用设置里授权目录。

## 2026-11-18 · 前端 bug

- **列表不自动加载**：只在点查询/切标签时请求 → 改为启动、扫描结束、补全结束都刷新。
- **全选/删除无响应**：插入代码时把事件监听器写进了「保存设置」的点击函数体内，页面加载时不注册。
  - 教训：往 `app.js` 追加逻辑必须显式定位到文件末尾，不能用 `replace('refresh();')` 这种模糊锚点。
- **扫描计数恒为 0/0**：扫描任务从不累加 ok/fail → 改为任务写入 `summary` 文本，界面优先显示摘要。

## 2026-11-18 · 检索阶梯 + 人工选版（0.4.0）

按产品要求实现按序降级的检索：

1. L1 歌名 + 演唱者
2. L2 去括号 / 去 feat.
3. L6 繁简转换（opencc-js）
4. L3 歌名 + 专辑
5. L7 去副标题（Live/Remastered/OST）
6. L4 仅歌名
7. L5 文件名原文

- 每级采纳条件：分数 ≥ 55 **且** 时长差 ≤ 5 秒。
- 三种下载模式：全自动 / 多版本时询问（默认）/ 全部人工。
- 「待确认」页：列候选（来源/歌名/歌手/专辑/时长/分数 + 歌词预览），点选写入。
- **选择记忆**：同一「歌手+歌名」选择过的版本会记住并在后续优先考虑。
