# musicTB · 调研与架构（v0.1 草案）

日期：2026-11-18

## 一、飞牛 fnOS 应用机制（已核对官方开发者文档 developer.fnnas.com）

### 应用包 = .fpk
根目录必须有：
```
manifest           应用元数据（appname/version/display_name/desc/source/platform/
                   maintainer/os_min_version/service_port/ctl_stop/desktop_uidir/
                   desktop_applaunchname/disable_authorization_path/changelog）
config/privilege   以哪个用户身份运行（run-as: package 专用用户 / root）
config/resource    资源声明：data-share / usr-local-linker / docker-project / api-scope
cmd/               生命周期脚本：install_init、install_callback、main、upgrade_*、
                   uninstall_*、config_*（main 处理 start/stop/status，退出码 0/1/3）
app/               运行文件与 UI（desktop_uidir 默认 ui）
wizard/            安装/升级/卸载/配置表单
ICON.PNG / ICON_256.PNG
```

### 安装后目录
`/var/apps/{appname}`，其中 target→/vol{n}/@appcenter/{appname}，
etc→@appconf，var→@appdata，home→@apphome，tmp→@apptemp。
用环境变量 TRIM_APPDEST / TRIM_PKGETC / TRIM_PKGVAR / TRIM_DATA_SHARE_PATHS，不要硬编码。

### 两种运行方式
1. **原生应用**：cmd/main 里直接启动自带二进制/运行时。
2. **Docker 应用**：config/resource 声明 docker-project + app/docker/docker-compose.yaml。

### 用户文件访问（关键）
- 应用以独立「包用户」运行，默认**没有**用户文件权限。
- 需要用户/管理员**授权目录**，系统把该路径 ACL 授予包用户后才能真正读写。
- 授权方式：
  - 用户在应用设置里添加授权目录（manifest `disable_authorization_path=false` 时才显示）
  - 应用内调用 JS SDK `pickUserFile / pickSharedFile` 直接弹目录选择器（需 manifest `micro_app=true`）
  - 后端通过 Unix Socket `/var/run/trim_open_gateway_apiscope.socket` 调 `POST /api/v1/trimapp` 查询授权路径（scope：trim.file.sharedAccess / trim.file.userAccess / trim.file.userAcl / trim.file.path / trim.system.getPlatformConfig）
- 结论：读音乐目录 + 写 .lrc 完全可行，走授权目录即可。

### 工具链
- fnpack 1.2.3（win-x64 / linux-x64 / linux-arm64 / mac）
  - `fnpack create <appname>`、`--without-ui true`、`--template docker`、`fnpack build`
- appcenter-cli：本地包安装/调试、应用中心流程

## 二、歌词源实测（2026-11-18，本机直连）

| 源 | 搜索 | 取歌词 | 结果 |
|---|---|---|---|
| LRCLIB | /api/search | 同响应内 syncedLyrics | ✅ 可用（晴天→20 条，带时间轴） |
| 网易云 | /api/search/get/web | /api/song/lyric | ✅ 可用（返回逐行 LRC） |
| QQ音乐 | client_search_cp | fcg_query_lyric_new | ✅ 可用（需 Referer: y.qq.com） |
| 酷狗 | mobilecdn search/song | krcs.kugou.com/search → lyrics.kugou.com/download | ✅ 可用（base64 LRC，1455 字节） |
| 酷我 | search.kuwo.cn/r.s（pseudo-JSON，需把 ' 换 "） | m.kuwo.cn newh5 / newlyric | ⚠️ 搜索通，歌词接口全部「音乐查询失败」，需再攻（可能需新版签名/cookie） |
| 咪咕 | m.music.migu.cn scr_search_tag | getLyric | ❌ 搜索已无数据（接口下线） |

技术要点：
- 歌词接口大多无需登录；酷狗要两步（hash→candidate→download）。
- 匹配必须靠 **时长 ±时长容差 + 歌名 + 歌手**，否则同名翻唱/KTV 伴奏/Remix 会污染。
- QQ/网易有 base64 与 JSON 两种返回，需按参数处理。

## 三、架构建议

```
musicTB (fpk)
├─ cmd/            生命周期脚本（start/stop/status）
├─ manifest        service_port=port, disable_authorization_path=false, micro_app=true
├─ config/
│   ├─ privilege   run-as=package
│   └─ resource    api-scope: trim.file.userAccess/... ；data-share: musictb/data
├─ app/
│   ├─ server/     Node 后端（自带 node 二进制，x86/arm 各一份）
│   │   ├─ scan     目录扫描 + 标签读取（music-metadata）
│   │   ├─ match    打分匹配
│   │   ├─ sources/ 内置源（lrclib/netease/qq/kugou/…）+ 用户源加载目录
│   │   ├─ write    写 .lrc（UTF-8），可选内嵌标签
│   │   └─ api      HTTP API + SQLite 记录（命中、失败、重试）
│   └─ ui/         静态前端（Vue/原生），fnOS 桌面入口
└─ wizard/         安装向导：选音乐目录、选默认源
```

### 源插件机制（需求 4）
- 内置源：`sources/*.js`，统一接口
  ```js
  export default {
    name, displayName,
    async search(track) { return [{ title, artist, album, duration, lrc }] }
  }
  ```
- 用户源：放在数据目录 `sources/`，界面提供「模板下载 / 粘贴保存 / 测试」按钮，并写明：自定义源由用户自行提供，执行的是用户代码。
- 内置源可单独启停、排序、设置超时与并发。

### 流程
扫描（增量，跳过已有 .lrc）→ 匹配打分（低于阈值不写）→ 多源取词 → 写 .lrc → 记录报告
失败可重试；同名不同版按时长区分；全部写入前先备份到应用 data 目录。
